<details>
<summary>&nbsp;▸&nbsp; <strong>V &nbsp;·&nbsp; Clustering</strong> &nbsp;—&nbsp; <code>notebooks/04_clustering.ipynb</code></summary>
<br>

Segmentación no supervisada sobre el espacio preprocesado con **K-Means** como modelo principal y **DBSCAN** como comparación.

**Selección del K óptimo:** se evaluaron K=2 a K=10 con método del codo (inercia) y Silhouette score. K=2 tiene el silhouette más alto (0.49) pero redescubre trivialmente "Tinto vs. el resto" → una separación que ya teníamos como columna. Se eligió **K=8** como el siguiente máximo real (silhouette=0.37), que coincide con el codo de inercia y produce agrupaciones con coherencia enológica.

**DBSCAN (comparación):** con eps=1.5, min_samples=10 genera 12 clusters pero deja el 3.9% de vinos sin asignar (ruido). Un recomendador necesita cubrir el 100% del catálogo, por lo que se descartó como modelo principal.

**Prueba de estabilidad:** K-Means repetido con 5 semillas distintas (0, 1, 42, 123, 2024) → Adjusted Rand Index entre los 10 pares posibles = **1.0** en todos los casos. El clustering es totalmente estable.

<details>
<summary>&nbsp;▸&nbsp; <strong>VIII &nbsp;·&nbsp; MLOps — Pipeline reutilizable</strong> &nbsp;—&nbsp; <code>src/</code></summary>
<br>

Los notebooks entrenan el modelo, pero no sirven para producción: cada vez que se ejecutan **re-ajustan** el scaler y el K-Means desde cero, lo que daría resultados distintos para el mismo vino. El pipeline MLOps resuelve esto: **entrenar una vez, predecir siempre sin reentrenar**.

Los tres objetos entrenados (StandardScaler, K-Means y PCA) se serializan juntos en `models/inwine_pipeline.joblib` con `joblib.dump()`. Cuando llega un vino nuevo, se cargan con `joblib.load()` y se aplican con `.transform()` / `.predict()` — nunca `.fit()`.

<br>

**Archivos**

| Script | Qué hace |
| :--- | :--- |
| `src/train_pipeline.py` | Carga el CSV, llama a `preprocess()`, entrena K-Means (K=8) y PCA (2D), guarda el artefacto `.joblib` |
| `src/predict_pipeline.py` | Carga el artefacto, aplica Target Encoding + escalado + K-Means + PCA a un DataFrame nuevo, y opcionalmente lo añade al catálogo CSV |
| `src/add_wine.py` | CLI interactivo: pregunta los datos campo a campo, valida, muestra resumen, llama a `predict_pipeline` y añade el vino al catálogo |

<br>

**Flujo de datos**

```
wines_SPA_enriched_FINAL.csv
        │
        ▼
  train_pipeline.py
  ┌───────────────────────────────────────┐
  │  preprocess()  →  StandardScaler.fit  │
  │  KMeans.fit(X)                        │
  │  PCA.fit(X)                           │
  └──────────────┬────────────────────────┘
                 │ joblib.dump()
                 ▼
     models/inwine_pipeline.joblib
                 │
                 │ joblib.load()   (sin reentrenar)
                 ▼
  predict_pipeline.py / add_wine.py
  ┌───────────────────────────────────────┐
  │  scaler.transform()    ← NO .fit()   │
  │  kmeans.predict()      ← NO .fit()   │
  │  pca.transform()       ← NO .fit()   │
  └──────────────┬────────────────────────┘
                 ▼
     cluster_id  ·  PC1  ·  PC2
     → append_to_catalog()
     → wines_SPA_enriched.csv  (la app)
```

<br>

**Por qué `.transform()` y no `.fit_transform()`**

`fit_transform()` recalcula la media y la desviación estándar sobre los nuevos datos. Si el vino nuevo tiene un precio de 35 €, la media del scaler cambia a 35 € — completamente distinta a la del entrenamiento (50 € de media sobre 2.024 vinos). El cluster asignado sería incorrecto porque la escala ha cambiado. Con `.transform()`, el scaler usa **la misma media y desviación que aprendió en entrenamiento**, garantizando comparabilidad.

<br>

**Cuándo volver a ejecutar `train_pipeline.py`**

| Situación | ¿Re-entrenar? |
| :--- | :---: |
| Añadir un vino nuevo | ✗ No — usar `add_wine.py` |
| El dataset base cambia (nuevos vinos del scraper) | ✓ Sí |
| Se modifica `preprocessing.py` | ✓ Sí |
| Se cambia el número de clusters K | ✓ Sí |

<details>
<summary>&nbsp;▸&nbsp; <strong>V &nbsp;·&nbsp; Clustering</strong> &nbsp;—&nbsp; <code>notebooks/04_clustering.ipynb</code></summary>
<br>

Unsupervised segmentation on the preprocessed space using **K-Means** as the primary model and **DBSCAN** as a comparison.

**Optimal K selection:** K=2 to K=10 evaluated using the elbow method (inertia) and Silhouette score. K=2 has the highest silhouette (0.49) but trivially recovers "Red vs. everything else" — a separation already present as a column. **K=8** was selected as the next real peak (silhouette=0.37), coinciding with the inertia elbow and producing enologically coherent clusters.

**DBSCAN (comparison):** with eps=1.5, min_samples=10 it finds 12 clusters but leaves 3.9% of wines unassigned (noise). A recommender needs to cover 100% of the catalogue, so it was discarded as the primary model.

**Stability test:** K-Means repeated with 5 different seeds (0, 1, 42, 123, 2024) → Adjusted Rand Index across all 10 pairs = **1.0**. The clustering is fully stable.

| :---: | :--- | :---: | :---: |
| 0 | Icons of Ageing — top-tier reserves, Ribera / Priorat | ~€540 | — |
| 1 | Select Whites — Atlantic and Rueda premium | ~€48 | — |
| 2 | Young Author Reds — emerging regions | ~€46 | — |
| 3 | Singular Wines — eclectic and versatile | ~€34 | — |
| 4 | Fortified & Jerez — Montilla-Moriles, flor-aged | ~€113 | — |

<details>
<summary>&nbsp;▸&nbsp; <strong>VIII &nbsp;·&nbsp; MLOps — Reusable Pipeline</strong> &nbsp;—&nbsp; <code>src/</code></summary>
<br>

The notebooks train the model, but they are not suitable for production: every time they run they **refit** the scaler and K-Means from scratch, which would produce different results for the same wine. The MLOps pipeline solves this: **train once, predict always without retraining**.

The three trained objects (StandardScaler, K-Means and PCA) are serialised together into `models/inwine_pipeline.joblib` with `joblib.dump()`. When a new wine arrives, they are loaded with `joblib.load()` and applied with `.transform()` / `.predict()` — never `.fit()`.

<br>

**Scripts**

| Script | What it does |
| :--- | :--- |
| `src/train_pipeline.py` | Loads the CSV, calls `preprocess()`, trains K-Means (K=8) and PCA (2D), saves the `.joblib` artifact |
| `src/predict_pipeline.py` | Loads the artifact, applies Target Encoding + scaling + K-Means + PCA to a new DataFrame, and optionally appends it to the catalog CSV |
| `src/add_wine.py` | Interactive CLI: asks for data field by field, validates, shows a summary, calls `predict_pipeline` and appends the wine to the catalog |

<br>

**Why `.transform()` and not `.fit_transform()`**

`fit_transform()` recalculates the mean and standard deviation on the new data. If the new wine has a price of €35, the scaler's mean changes to €35 — completely different from the training mean (€50 over 2,024 wines). The assigned cluster would be incorrect because the scale has changed. With `.transform()`, the scaler uses **the same mean and standard deviation it learned during training**, guaranteeing comparability.

<br>

**When to re-run `train_pipeline.py`**

| Situation | Retrain? |
| :--- | :---: |
| Adding a new wine | ✗ No — use `add_wine.py` |
| Base dataset changes (new wines from the scraper) | ✓ Yes |
| `preprocessing.py` logic is modified | ✓ Yes |
| Number of clusters K changes | ✓ Yes |

<br>

**Tests — `tests/test_pipeline.py`**

11 tests with synthetic fixtures (no real CSV needed):

```bash

```

## ✦ &nbsp; Sesgos éticos

<br>

Un modelo de clustering no es neutral. Las decisiones de preprocesamiento y la composición del dataset introducen patrones que afectan qué vinos se recomiendan y qué regiones quedan invisibilizadas.

<br>

<div align="center">

| Sesgo | Descripción | Riesgo |
| :--- | :--- | :---: |
| **Económico** | C0 (€541 de media) cuesta 16× más que C3 (€34) → el modelo amplifica vinos de lujo si no se filtra por presupuesto | 🔴 Alto |
| **Desbalance de tipos** | El 84 % del dataset son tintos (1.699 de 2.016) → blancos, espumosos y generosos tienen clusters de < 140 vinos, con variedad de recomendación muy reducida | 🔴 Alto |
| **Concentración geográfica** | Rioja y Ribera del Duero dominan 5 de 8 clusters → las D.O. emergentes (Terra Alta, Utiel-Requena, Lanzarote) quedan sistemáticamente infrarrepresentadas | 🟡 Medio |
| **Rating de críticos** | El rating proviene de críticos especializados, no consumidores: correlaciona con el precio, haciendo que el modelo equipare exclusividad con calidad | 🟡 Medio |
| **Demográfico** | Sin datos de usuario (edad, género, ubicación) → el riesgo de discriminación de personas es bajo | 🟢 Bajo |

</div>

<br>

**Medidas ya aplicadas:**

| Medida | Sesgo que mitiga |
| :--- | :--- |
| Filtro duro de presupuesto | Económico → excluye vinos de lujo fuera del rango del usuario |
| Dual scoring calidad-precio | Económico → puntúa el ratio, no solo el rating ni el precio |
| Sección `/valor` con ranking por ratio | Geográfico / Económico → visibiliza vinos buenos y baratos de D.O. pequeñas |
| Explicación en cada recomendación | Rating de críticos → el usuario entiende por qué se eligió ese vino |

<br>

<details>
<summary><strong>English</strong></summary>
<br>

A clustering model is not neutral. Preprocessing decisions and the dataset composition introduce patterns that affect which wines get recommended and which regions become invisible.

<br>

<div align="center">

| Bias | Description | Risk |
| :--- | :--- | :---: |
| **Economic** | C0 (€541 avg) costs 16× more than C3 (€34) → the model amplifies luxury wines if budget is not filtered | 🔴 High |
| **Type imbalance** | 84 % of the dataset is red wine (1,699 of 2,016) → whites, sparkling and fortified wines have clusters of < 140 wines, with very limited recommendation variety | 🔴 High |
| **Geographic concentration** | Rioja and Ribera del Duero dominate 5 of 8 clusters → emerging D.O. regions (Terra Alta, Utiel-Requena, Lanzarote) are systematically under-represented | 🟡 Medium |
| **Critic ratings** | Ratings come from specialist critics, not consumers: they correlate with price, causing the model to equate exclusivity with quality | 🟡 Medium |
| **Demographic** | No user data (age, gender, location) → risk of person-level discrimination is low | 🟢 Low |

</div>

**Mitigations already applied:**

| Measure | Bias it mitigates |
| :--- | :--- |
| Hard budget filter | Economic → excludes luxury wines outside the user's range |
| Dual quality-price scoring | Economic → scores the ratio, not just the rating or the price |
| `/valor` section with ratio ranking | Geographic / Economic → surfaces good cheap wines from small D.O. regions |
| Explanation on every recommendation | Critic ratings → the user understands why that wine was chosen |
